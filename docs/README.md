# مستندات و بسته‌بندی

| فایل | توضیح |
|---|---|
| `demo-report-FA.md` / `.html` | گزارش پژوهش دمو و طرح اجرای لندینگ؛ منبع تصمیم‌های فاز ۹ |
| `changelog-FA.txt` | تاریخچهٔ تغییرات نسخهٔ فعلی (۳.۱.۳) |
| `licensing-FA.md` | مشخصات فایل لایسنس راست‌چین، دروازهٔ لایسنس، بلوک الزامی محافظت و چک‌لیست صدور مجدد |
| `security-report-FA.md` | گزارش بررسی‌های امنیتی |
| `load-report-FA.md` | گزارش تست بار و پایداری |
| `optimization-*.md` | ممیزی و نتیجهٔ بهینه‌سازی کوئری‌ها |
| `sso-design-FA.md` | طراحی ورود گوگل و تلگرام |

## ساخت بستهٔ افزونه

```sh
python3 scripts/package-deliverables.py                 # ashna.zip (لایسنس‌دار)
python3 scripts/package-deliverables.py --without-license  # ashna-no-license.zip
```

خروجی در `deliverables/` نوشته می‌شود و `checksums.json` بازسازی می‌شود. در ساخت
لایسنس‌دار، بستهٔ تحویل `deliverables/ashna-package-fa.zip` هم از همان `ashna.zip`
به‌همراه `help.pdf` (با نام `Ashna-Guide-FA.pdf`) و یک `README-FA.txt` ساخته می‌شود.
اسکریپت قبل از بسته‌بندی، SHA-1 فایل لایسنس را با ثابت `LICENSE_SHA1` در `ashna.php` تطبیق می‌دهد و در صورت نخواندن هش، بسته‌سازی را متوقف می‌کند؛ بعد
از بسته‌بندی، نبود نام برند قبلی را داخل ZIP بررسی می‌کند.

## لندینگ

لندینگ آشنا در `ashna-landing/` است و راهنمای استقرار و ویرایش آن در
`ashna-landing/README-FA.md` آمده است. این پوشه به وردپرس وابسته نیست.

## خرابی‌های شناخته‌شده

- راهنمای PDF فارسی خریدار هنوز بازسازی نشده است؛ با حذف دارایی‌های برند قبلی، نسخهٔ قدیمی هم حذف شد.
  PDF جدید باید از متن آشنا ۳.۱.۳ ساخته شود (فاز ۱۰ چک‌لیست).
- اسکرین‌شات‌های واقعی پنل هنوز جایگزین بازسازی HTML در لندینگ نشده‌اند؛ روش جایگزینی در README لندینگ آمده است.
