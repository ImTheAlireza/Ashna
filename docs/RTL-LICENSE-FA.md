# لایسنس‌گذاری راست‌چین — چیدمان، قواعد محافظت فایل و روند ارسال

این سند پاسخ «سیستم لایسنس راست‌چین دوباره چک شود» و «بقیه‌اش را ردیف کن» است:
قواعد رسمی راست‌چین (پنل فروشنده → ارسال محصول)، اینکه کدام فایل باید محافظت شود،
و روند دقیق ارسال.

## ۱. قواعد لایسنس راست‌چین

| قاعده | معنی برای آشنا |
|---|---|
| محافظت فایل فقط با سرویس راست‌چین انجام می‌شود (رایگان و نامحدود) | هر بار کد را تغییر دادی، همان فایل را دوباره ارسال کن |
| بدون «افزونهٔ مدیریت لایسنس راست‌چین» و لایسنس فعال، محصول نباید قابلیتی بدهد | بارگذار لایسنس پیش از بالا آمدن محصول برمی‌گردد |
| فایل لایسنس مخصوص همین محصول است؛ نام و محتوایش تغییر نکند | `RTL_License_c1595a7238d64f3a.php` فقط کنار فایل‌ها قرار می‌گیرد |
| فایل لایسنس داخل پوشهٔ اصلی افزونه قرار می‌گیرد (همان پوشه‌ای که `ashna.php` در آن است) | مسیر در کد با `__DIR__` ساخته می‌شود |
| ionCube Loader باید روی هاست مشتری فعال باشد | اگر نباشد، قبل از `require` تشخیص داده می‌شود (بدون صفحهٔ سفید) |
| لایسنس به دامنه قفل می‌شود؛ ساب‌دامین لایسنس جدا دارد | کار خریدار است؛ در کد دخالتی ندارد |

## ۲. قواعد «محافظت فایل» (صفحهٔ ارسال محصول)

| قاعدهٔ راست‌چین | وضعیت در آشنا |
|---|---|
| فقط فایل PHP معمولی / ترکیب PHP و HTML قابل محافظت است | ✔ |
| حداکثر ۱ مگابایت برای هر فایل PHP | ✔ `ashna-core.php` حدود ۱٫۵ کیلوبایت است |
| فایل خالی پشتیبانی نمی‌شود | ✔ |
| Short tag به شکل `<? ?>` پشتیبانی نمی‌شود | ✔ همهٔ فایل‌ها `<?php` هستند |
| `__halt_compiler()` پشتیبانی نمی‌شود | ✔ |
| `include`/`require` بدون مبنای مسیر پشتیبانی نمی‌شود | ✔ مبنای مسیر **داخل خودِ دستور** است؛ سرویس، `require $file;` را حتی وقتی `$file` از `__DIR__` ساخته شده باشد رد می‌کند |
| **فایل اصلی افزونه (دارای `Plugin Name`) را ارسال نکنید** | ✔ `ashna.php` هرگز ارسال نمی‌شود |
| **فایلی که `Loader` لایسنس داخل آن است را ارسال نکنید** | ✔ `ashna-license.php` هرگز ارسال نمی‌شود |
| نام و محتوای فایل محافظت‌شده را بعد از دریافت تغییر ندهید | خروجی سرویس را همان‌طور با نام `ashna-core.php` جای‌گذاری کن |
| اگر ZIP می‌فرستی: ۲ تا ۵ فایل PHP، حداکثر ۶ مگابایت | `scripts/prepare-protection-batches.py` دقیقاً همین را می‌سازد (§۷) |

خلاصهٔ عملی: **تنها فایلی که به سرویس محافظت فرستاده می‌شود `ashna-core.php` است.**
`ashna.php` و `ashna-license.php` متن ساده می‌مانند، چون راست‌چین صریحاً ارسال آن‌ها را
منع کرده است.

## ۳. چیدمان فایل‌ها

```
ashna/
├── ashna.php                  ← هدر افزونه + ثابت‌ها (متن ساده — ارسال نکن)
├── ashna-license.php          ← بارگذار لایسنس + تشخیص‌ها (متن ساده — ارسال نکن)
├── ashna-core.php             ← ★ تنها فایلی که برای محافظت ارسال می‌شود
├── RTL_License_<hash>.php     ← فایل لایسنس صادرشدهٔ راست‌چین (دست نزن)
├── includes/  assets/  templates/  languages/
└── index.php  uninstall.php
```

چرا این تقسیم‌بندی:

- وردپرس هدر `Plugin Name:` را از `ashna.php` می‌خواند؛ اگر این فایل محافظت شود،
  افزونه از فهرست «افزونه‌ها» محو می‌شود (فایل ionCube متن خوانا برای وردپرس ندارد).
- بارگذار لایسنس هم طبق قاعدهٔ صریح راست‌چین باید خوانا بماند؛ پس در فایل جداگانهٔ
  `ashna-license.php` است و هیچ کد محصولی در آن نیست.
- محصول (اتولودر، تابع `ashna_otp()` و راه‌اندازی هسته) در `ashna-core.php` است:
  بدون آن هیچ سرویس، منو، شورت‌کد، مسیر REST، ویجت المنتور یا فایل فرانت بارگذاری نمی‌شود.

## ۴. روند ارسال (گام‌به‌گام)

1. `python3 tests/run-protection-readiness.py` و
   `php -l ashna-core.php` — بدون خطا.
2. در پنل فروشندهٔ راست‌چین: «ارسال محصول» → بخش محافظت فایل →
   فقط `ashna-core.php` را آپلود کن.
3. خروجی محافظت‌شده را با همان نام `ashna-core.php` در ریشهٔ پوشهٔ `ashna/` بگذار
   (فایل با `<?php //ICB0 …` شروع می‌شود). فایل را باز، ویرایش یا ترکیب نکن.
4. `python3 scripts/package-deliverables.py` و بعد `ashna-core.php` را داخل
   `deliverables/ashna.zip` با نسخهٔ محافظت‌شده جای‌گزین کن.
5. روی سایت آزمایشی (با ionCube Loader و «مدیریت لایسنس راست‌چین»):
   بدون لایسنس → پیام و بی‌اثر بودن؛ با لایسنس → همهٔ امکانات.

> فایل لایسنس `RTL_License_c1595a7238d64f3a.php` را خودت کنار فایل‌ها می‌گذاری
> (داخل پوشهٔ اصلی افزونه). نام و محتوایش را تغییر نده: هش `sha1`
> `321791ab0231890e4569d17c52e64ed93d2eb42d` در `ashna-license.php` همین فایل را تأیید می‌کند.

## ۵. رفتار دروازه

| وضعیت | کد | نتیجه |
|---|---|---|
| «مدیریت لایسنس راست‌چین» نصب/فعال نیست | `license_manager_missing` | بی‌اثر + متن تأییدشدهٔ راست‌چین با لینک راهنما |
| فایل لایسنس نیست | `license_file_missing` | بی‌اثر + اعلان |
| هش فایل لایسنس نمی‌خواند | `license_hash_mismatch` | بی‌اثر + اعلان |
| ionCube Loader روی PHP وب نیست | `license_loader_missing` | بی‌اثر؛ بدون صفحهٔ سفید |
| کلاس از فایل دیگری بار شده | `license_class_conflict` | بی‌اثر |
| `isActive()` مقدار غیر `true` داد | `license_inactive` | بی‌اثر؛ اعلان تکراری چاپ نمی‌شود |
| خطای اجرا در فایل لایسنس | `license_runtime_error` | بی‌اثر؛ متن خطا لو نمی‌رود |
| `ashna-core.php` نیست | `license_core_missing` | بی‌اثر + اعلان |
| `ashna-license.php` حذف شده | `license_gate_missing` | بی‌اثر + اعلان |

در همهٔ حالت‌ها هیچ منو، شورت‌کد، REST route، ویجت المنتور، دارایی فرانت یا جدولی ثبت
نمی‌شود و در ردیف افزونه لینک «فعال‌سازی لایسنس» می‌آید.

## ۷. محافظت کامل کد محصول

`ashna-core.php` تنها فایلی نیست که باید بفرستی؛ ارزش واقعی محصول در `includes/`
است (۴۷ فایل، ۸۵۰ کیلوبایت، بزرگ‌ترین فایل ۱۴۹ کیلوبایت). آماده‌سازی خودکار:

```sh
python3 scripts/prepare-protection-batches.py
```

خروجی در `deliverables/protection/`:

- `ashna-core.php` به‌تنهایی (آپلود تکی، بدون ZIP)؛
- `batch-01.zip` … `batch-10.zip` — هر بسته ۵ فایل PHP، همه زیر سقف ۱ مگابایت
  برای هر فایل و ۶ مگابایت برای هر ZIP؛
- `MANIFEST.json` (فهرست دقیق هر بسته + sha256) و `README-FA.txt` (راهنمای گام‌به‌گام).

بعد از دریافت فایل‌های محافظت‌شده:

```sh
python3 scripts/apply-protected-files.py --from <پوشهٔ خروجی‌ها>
```

اسکریپت هر فایل را با امضای ionCube بررسی می‌کند، با همان مسیر داخل بسته جای
می‌گذارد و `deliverables/ashna-protected.zip` می‌سازد؛ اگر فایلی جا افتاده باشد
فهرست «هنوز متن ساده» را چاپ می‌کند. کد مخزن دست‌نخورده می‌ماند.

چه چیزی عمداً متنی می‌ماند: `ashna.php`، `ashna-license.php`، فایل لایسنس،
`includes/index.php`ها (فایل خالی پذیرفته نمی‌شود) و `templates/` (برای اینکه
خریدار بتواند ظاهر فرم ورود را شخصی‌سازی کند).

### گارد ورودی

`ashna-core.php` پیش از هر کاری بررسی می‌کند که لایسنس تأیید شده باشد
(`Ashna_License_Bootstrap::granted()`)، وگرنه `return` می‌کند؛ چون این فایل رمز
می‌شود، `require` مستقیم آن بدون عبور از دروازه هیچ چیزی را بوت نمی‌کند
(سناریوی `direct_bypass`).

نکتهٔ فنی مهم: همین گارد را **نمی‌توان** بالای فایل‌های کلاسی (`includes/*.php`)
گذاشت؛ PHP اعلان کلاس را هنگام کامپایل bind می‌کند و `return` بالای آن دیر است —
کلاس تعریف می‌شود. پس گارد فقط در فایل ورودی معنا دارد و بقیهٔ محافظت از جنس
رمزگذاری است، نه گارد.

### قاعدهٔ سخت‌گیرانه‌ای که سرویس واقعاً اعمال می‌کند

تحلیل‌گر سرویس، خودِ دستور را می‌خواند: `require $file;` و `include $theme_template;` را
رد می‌کند حتی اگر آن متغیر چند خط بالاتر از `__DIR__` ساخته شده باشد. پس:

- `require __DIR__ . '/../' . self::$class_map[ $class_name ];` ✅
- `$file = __DIR__ . '/../' . ...; require $file;` ❌

در نتیجه: اتولودر مسیر را دوباره داخل دستور می‌سازد، پارشال‌ها با
`__DIR__ . '/partials/...'` صدا زده می‌شوند، و بازنویسی قالب تم با
`get_stylesheet_directory()` / `get_template_directory()` انجام می‌شود (هر دو در فهرست
مبناهای مجاز راست‌چین هستند).

### مرز واقعی

هیچ‌کدام از این‌ها نال‌کردن را غیرممکن نمی‌کند؛ هدف این است که خواندن/کپی/ویرایش
کد ممکن نباشد و زحمت نال از قیمت محصول بیشتر شود. راه‌های باقی‌مانده برای یک
نال‌کننده همان سه مورد §۲ است (ویرایش فایل‌های متنی)، ولی دیگر هیچ کد محصولی
قابل خواندن و بازنویسی نیست.

## ۸. دو نکتهٔ باقی‌مانده

- نسخهٔ لایسنس‌دار `Requires PHP: 8.2` اعلام می‌کند و نسخهٔ بدون لایسنس
  (`scripts/templates/ashna-no-license.php`) هنوز `7.4` است؛ کد فعلی از نظر نحوی روی
  ۷٫۴ هم پارس می‌شود، پس یکی از این دو عدد باید یکسان شود. تصمیم محصولی است و تا
  اعلام تو تغییر نکرده.
- `includes/` باز می‌ماند (§۷)؛ فقط اجرای فایل محافظت‌شده از مسیر لایسنس انجام می‌شود.
