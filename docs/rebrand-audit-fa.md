# گزارش تغییر هویت افزونه به آشنا / Ashna

تاریخ: ۱۴ اکتبر ۲۰۲۶ · نسخهٔ کد: ۲.۷.۷

## بررسی پیش از اجرا

در بررسی اولیهٔ فایل‌های ثبت‌شدهٔ مخزن، **۸۱ فایل متنی و ۴۷۱۴ رخداد نام قبلی** شناسایی شد. خروجی‌های باینری، تصاویر، PDF و ZIPها نیز جداگانه بررسی شدند؛ تغییر نام فایل به‌تنهایی برای آن‌ها کافی نبود.

| محدوده | تغییر انجام‌شده |
|---|---|
| ورودی وردپرس و بوت‌استرپ | هدر افزونه «آشنا»، فایل `ashna.php`، ثابت‌های `ASHNA_OTP_*`، تابع `ashna_otp()`، دامنهٔ ترجمه `ashna-otp` |
| کلاس‌ها و بارگذار | کلاس‌های `Ashna_*` و نام فایل‌های `class-ashna-*`؛ مسیرهای autoloader و requireها هماهنگ شدند |
| پیشخوان | عنوان و منو، تنظیمات، پیش‌نمایش، ابزارها، لاگ‌ها، خروجی‌ها، nonceها و درخواست‌های AJAX |
| فرم و قالب‌ها | شورت‌کدهای `ashna_otp_login`، `ashna_otp_form`، `ashna_otp_button` و `ashna_passkey_manager`؛ قالب ورود، ایمیل و ووکامرس |
| فرانت‌اند | کلاس‌های CSS، متغیرهای رنگ، IDها، JS globals و actionهای جدید با پیشوند `ashna` |
| المنتور | دسته و عنوان آشنا؛ ویجت‌های جدید و alias پنهان برای شناسه‌های ذخیره‌شدهٔ قبلی |
| لوگو | سپر آبی با در نیمه‌باز، بدون فلش؛ SVG واقعی و PNG شفاف؛ لوگوی افقی فارسی و نسخه سفید، آیکون منو و بستهٔ لوگو |
| سایت معرفی | نام و لوگوی محصول آشنا در لندینگ؛ برند مستقل گروه توسعهٔ پارسنا تغییر نکرده است |
| تصاویر | رندر مجدد هر هشت WebP، کاورهای JPG و thumbnail؛ به‌روزرسانی manifest و ZIPهای گالری |
| مستندات | README، راهنمای HTML و PDF فارسی سه‌صفحه‌ای، changelog و دستورالعمل نصب/ارتقا |
| ابزارها و خروجی‌ها | ابزار عیب‌یابی آشنا، تست‌ها، اسکریپت‌های build، بسته‌های لایسنس‌دار و بدون لایسنس، بستهٔ راست‌چین و checksumها |

## استثناهای عمدی: سازگاری، نه برند قدیمی

حذف بی‌قیدوشرط نام قبلی از دیتابیس، دسترسی به داده‌های نصب‌های قبلی را قطع می‌کند. به همین دلیل، **ذخیره‌سازی قبلی درجا استفاده می‌شود و مهاجرت مخرب یا کپی انبوه داده انجام نمی‌شود**. کد جدید از `Ashna_Storage` استفاده می‌کند:

- تنظیمات، نسخهٔ دیتابیس، جدول لاگ‌ها و قفل‌های امنیتی همان رکوردهای قبلی هستند.
- شمارهٔ موبایل، شناسهٔ بله، ثبت‌نام با OTP، کلیدهای عمومی Passkey و ایندکس credentialها تغییر محل نمی‌دهند.
- challengeها، توکن بله، کش‌ها و transientهای امنیتی، حتی با object cache خارجی، همان کلیدهای قبلی را دارند.
- تنظیم حالت تاریک، تب فعال و پرچم ثبت Passkey در مرورگر، بدون بازنویسی مقدار جدید، از کلیدهای قبلی کپی می‌شوند.
- شناسهٔ پایدار کاربر WebAuthn و job زمان‌بندی‌شدهٔ قبلی حفظ می‌شوند؛ زمان‌بندی تکراری ایجاد نمی‌شود.
- نام قبلی فقط در لایه‌های سازگاری، aliasها، fixtureهای تست و همین توضیح فنی باقی می‌ماند؛ نام نمایشی و namespace اصلی جدید است.

`Ashna_Compatibility` شورت‌کدهای قبلی، تابع، کلاس‌ها، interfaceها، ثابت‌ها و extension hookهای قبلی را پشتیبانی می‌کند. فیلترهای قدیمی قبل از فیلترهای جدید اعمال می‌شوند. رویدادهای قدیمی و جدید هرکدام یک بار dispatch می‌شوند.

ویجت‌های قبلی المنتور با همان IDهای ذخیره‌شده ثبت می‌شوند، اما از renderer جدید استفاده می‌کنند و در پنل افزودن ویجت نمایش داده نمی‌شوند. بنابراین نیازی به بازنویسی JSON/serialized postmeta نیست.

قالب جدید `yourtheme/ashna/login-form.php` اولویت دارد؛ مسیر قبلی نیز fallback است و selectorهای خروجی آن به namespace جدید تبدیل می‌شوند. CSS سفارشی ذخیره‌شده در تنظیمات نیز هنگام نمایش تبدیل می‌شود، بدون تغییر مقدار اصلی دیتابیس. کدهای سفارشی مستقل در قالب/افزونهٔ دیگر، CSS خارج از تنظیمات و فایل‌های کش‌شده باید در سایت مقصد بررسی شوند؛ این تغییر به معنی تست تمام افزونه‌های شخص ثالث نیست.

گزارش خصوصی و رضایت موقت ابزار تشخیص نیز در کلیدهای قبلی باقی می‌ماند تا پس از ارتقا قابل پاک‌کردن باشد. ابزار، پوشهٔ جدید و پوشهٔ قبلی افزونه را برای عیب‌یابی می‌شناسد.

## نصب و ارتقا

۱. از فایل‌ها و دیتابیس، تنظیمات و فایل رسمی لایسنس نسخهٔ پشتیبان بگیرید؛ ابتدا روی staging امتحان کنید.
۲. نسخهٔ قبلی را **غیرفعال** کنید. برای تغییر نام از دکمهٔ «حذف» وردپرس استفاده نکنید؛ تنظیم حذف داده‌ها ممکن است فعال باشد.
۳. پوشهٔ کامل `ashna-otp` را نصب کنید. فایل‌های دو پوشه یا دو نسخه را مخلوط نکنید. اگر نام پوشهٔ قبلی متفاوت است، نصب جدید یک افزونهٔ جدا در فهرست وردپرس خواهد بود.
۴. در نسخهٔ لایسنس‌دار، فایل معتبر رسمی را کنار `ashna.php` قرار دهید و سپس آشنا را فعال کنید. دو نسخه را هم‌زمان فعال نکنید.
۵. کش صفحه/CDN و مرورگر را پاک کنید؛ تنظیمات، شمارهٔ کاربر قدیمی، ورود OTP/Passkey، شورت‌کدهای قبلی، المنتور و ووکامرس را بررسی کنید.
۶. فقط پس از اطمینان از نصب جدید، آرشیو فایل‌های قدیمی را خارج از مسیر فعال سایت نگه دارید؛ uninstall نسخهٔ قدیمی را برای پاک‌سازی پوشه اجرا نکنید.

## لایسنس و محدودیت تأیید

نام فایل `RTL_License_c1595a7238d64f3a.php`، کلاس رسمی، هش `4f106eb02a251f2a6951ca3f530596590081002d` و شرط سخت‌گیرانهٔ `isActive() === true` تغییر نکرده‌اند. فایل رسمی در مخزن موجود نیست و فایل جعلی یا جایگزین ساخته نشده است. بستهٔ راست‌چین تا افزودن فایل رسمی، آمادهٔ انتشار نهایی نیست.

نسخهٔ بدون لایسنس مستقل، با بوت‌استرپ متنی خود ساخته می‌شود. حداقل PHP نسخهٔ لایسنس‌دار ۸.۲ و نسخهٔ بدون لایسنس ۷.۴ است. نسخهٔ دیتابیس عمداً ۲.۳.۰ باقی مانده است چون schema عوض نشده است.

لینک محصول در منبع لندینگ به `https://parsena.ir/ashna` تغییر کرده است. انتشار این مسیر و redirect آدرس قدیمی روی سایت واقعی، خارج از این مخزن است و انجام یا تأیید نشده است.

## کنترل کیفیت

- تست‌های bootstrap و لایسنس با dispatcher واقعی هوک وردپرس و سرویس‌های شبیه‌سازی‌شده؛ شامل دو سناریوی اختصاصی ارتقای هویت، در هر دو edition.
- fixture دادهٔ قدیمی: تنظیمات، جدول لاگ، cron، lockout، Passkey و ایندکس، ذخیرهٔ credential جدید و حذف credential قدیمی بدون بازگشت داده.
- alias شورت‌کد، کلاس، interface، hook و ویجت المنتور؛ حفظ واژه‌های استاندارد `signature` و `signal` در WebAuthn/JavaScript.
- تست‌های عیب‌یابی، حریم خصوصی، پیام‌های ionCube و حداقل PHP؛ این‌ها اجرای واقعی فایل رسمی ionCube نیستند.
- بررسی syntax PHP/JavaScript، layout و فونت PDF، یکسانی تایپوگرافی گالری، ابعاد و حجم تصاویر، سلامت ZIPها، مسیر فایل‌ها و SHA256 خروجی‌ها.

تست روی سایت زندهٔ مشتری، دیتابیس واقعی، ارسال واقعی SMS و فایل رسمی لایسنس انجام نشده است.
