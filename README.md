# آشنا / Ashna — ورود و ثبت‌نام وردپرس · نسخهٔ ۲.۷.۹

**آشنا / Ashna** یک افزونه جامع، سازمانی (Enterprise) و کاملاً ماژولار برای **ورود و ثبت‌نام یکپارچه کاربران با کد یکبارمصرف (OTP)** در وردپرس و ووکامرس است.

## هویت جدید و ارتقای امن

نام محصول **آشنا / Ashna** و نماد آن سپر آبی با در نیمه‌باز است. فایل ورودی داخلی `ashna.php` و پوشهٔ نصب `ashna-otp` هستند. نام و هویت تمام رابط‌ها، مستندات و خروجی‌ها هماهنگ شده‌اند.

**برای ارتقا:** بکاپ بگیرید، نسخهٔ قبلی را غیرفعال کنید، پوشهٔ کامل جدید را نصب و سپس فعال کنید. نسخهٔ قبلی را از طریق «حذف» وردپرس پاک نکنید و دو نسخه را هم‌زمان فعال نکنید. داده‌های قبلی، شورت‌کدها و ویجت‌های ذخیره‌شده از طریق لایهٔ سازگاری حفظ می‌شوند. [گزارش بررسی و دستورالعمل کامل](docs/rebrand-audit-fa.md).

## نشست و دسترسی بعد از ورود

آشنا برای OTP، رمز عبور و Passkey از **نشست و کوکی استاندارد وردپرس** (`WP_Session_Tokens`) استفاده می‌کند؛ JWT مستقل و سطح دسترسی جداگانه ندارد. نقش کاربر موجود حفظ می‌شود و مجوزهای ووکامرس از همان WP user ID پیروی می‌کنند. در نسخهٔ **۲.۷.۸** انتقال نشست مهمان با API رسمی ووکامرس و تازه‌سازی nonce بعد از ورود AJAX یکپارچه شده است.

[گزارش بررسی، اصلاحات و محدودیت تست‌ها](docs/session-authentication-fa.md) · تست‌ها شامل APIهای رسمی وردپرس/ووکامرس و هندآف nonce در Chromium هستند؛ جایگزین تست staging با ترکیب واقعی افزونه‌ها نیستند.

## نیازمندی‌های نسخهٔ لایسنس‌دار فعلی

- وردپرس ۵.۸ یا بالاتر.
- **PHP حداقل 8.2**؛ وردپرس در فعال‌سازی استاندارد، نسخه‌های پایین‌تر را رد می‌کند. این تغییر، PHP هاست را ارتقا نمی‌دهد.
- ionCube Loader فعال در PHP وب و سازگار با نسخهٔ PHP و فایل رمزگذاری‌شدهٔ لایسنس. حداقل PHP به معنی تضمین سازگاری فایل لایسنس با تمام نسخه‌های جدیدتر نیست.
- فایل رسمی `RTL_License_c1595a7238d64f3a.php` با همان هش قبلی `4f106eb02a251f2a6951ca3f530596590081002d`؛ نسخهٔ جایگزین مخصوص PHP 7.4 استفاده نمی‌شود.
- برای بستهٔ قابل نصب، از `deliverables/ashna-otp-with-logo.zip` استفاده کنید. فایل واقعی لایسنس در مخزن موجود نیست؛ پیش از نصب/جایگزینی، فایل معتبر متناظر را کنار `ashna.php` در بسته قرار دهید. از سایت و فایل لایسنس قبلی نسخهٔ پشتیبان بگیرید.

نسخهٔ جداگانهٔ بدون لایسنس و ابزار عیب‌یابی، نیازمندی‌های مستقل خود را دارند. پیش از تغییر PHP سایت اصلی، سازگاری قالب، پرداخت و افزونه‌ها را روی کپی آزمایشی بررسی کنید.

## امکانات کلیدی

### ۱. پشتیبانی از کانال‌ها و درگاه‌های متنوع + ۳ درگاه پشتیبان (Multi-Gateway Failover)
- **درگاه‌های پیامکی ایرانی (ارسال سریع خدماتی / پترن):**
  - **SMS.ir** (وب‌سرویس جدید REST v1 - `api.sms.ir/v1/send/verify`)
  - **فراز اس‌ام‌اس (FarazSMS)** (پشتیبانی از هر دو روش `API Key` و `نام کاربری / رمز عبور`)
  - **ملی‌پیامک (Melipayamak)** (وب‌سرویس خدماتی `BaseServiceNumber`)
  - **کاوه‌نگار (Kavenegar)** (وب‌سرویس اعتبارسنجی `verify/lookup.json`)
  - **آی‌پی‌پنل (IPPanel)** (پشتیبانی از وب‌سرویس جدید `Edge API`، `API Key` و کلاسیک)
  - **زنجیره ۳ درگاه پشتیبان خودکار (Failover Chain):** تعریف تا ۳ درگاه پشتیبان به ترتیب اولویت برای ارسال خودکار در صورت قطعی یا اتمام شارژ درگاه اصلی
- **پیام‌رسان بله (Bale Messenger):**
  - پشتیبانی از **وب‌سرویس رسمی سفیر بله (Safir OTP API)** و **ربات بله (Bale Bot API)**
  - قابلیت **ارسال هوشمند ترکیبی (Fallback)**: اول ارسال در بله و در صورت عدم عضویت کاربر، ارسال خودکار از طریق پیامک
- **ایمیل (`wp_mail`):** ارسال کد تایید با قالب HTML فارسی و ریسپانسیو
- **حالت تست / آزمایشی (Sandbox):** تست کامل فرآیند در محیط لوکال بدون نیاز به پنل پیامک

### ۲. داشبورد مدرن SaaS + استودیو طراحی زنده (Live Preview Studio)
- پنل مدیریت مدرن با منوی عمودی، حالت تاریک/روشن (Dark Mode) و ذخیره آنی AJAX (`Ctrl+S`)
- نمودار تحلیلی ۷ روزه، نرخ تبدیل (Conversion Rate) و بررسی سلامت سیستم
- استودیو طراحی ظاهر با پیش‌نمایش زنده ایزوله (Live Preview)، ۴ قالب آماده، انتخابگر رنگ و CSS سفارشی

### ۳. امنیت، مقابله با Brute Force و کاهش ریسک SMS Bombing
- **محدودسازی درخواست OTP در سرور، قبل از فراخوانی درگاه:** سقف جداگانه برای گیرنده (شماره/ایمیل) و IP؛ پیش‌فرض **۵ درخواست برای هر گیرنده و ۱۵ درخواست برای هر IP در ساعت گذشته**، قابل تنظیم.
- **فاصلهٔ ارسال مجدد:** پیش‌فرض **۶۰ ثانیه** برای همان گیرنده بر اساس آخرین رکورد غیر failed؛ مستقل از شمارش معکوس مرورگر. سقف‌های تعداد درخواست **ساعتی‌اند**؛ limiter مستقل IP در هر دقیقه در نسخهٔ فعلی وجود ندارد.
- **تفکیک دو تهدید:** محدودیت ارسال برای کاهش ریسک SMS Bombing و مصرف غیرعادی اعتبار پنل است؛ محدودیت تلاش تأیید، برای مقابله با حدس‌زدن کد/رمز است.
- پشتیبانی از **آرکپچا (Arcaptcha.ir)**، **کپچای ریاضی داخلی**، **Cloudflare Turnstile** و **Google reCAPTCHA v3**
- محدودیت پیش‌فرض **۵ تلاش ناموفق OTP** و **قفل موقت ۱۵ دقیقه‌ای** گیرنده و IP؛ شمارش تلاش‌های ناموفق رمز عبور، نمایش قفل‌های فعال و امکان رفع مسدودی در مدیریت.
- لیست سیاه شماره/IP با پشتیبانی از الگوی `*` و لیست سفید با تطبیق دقیق. **whitelist از محدودیت درخواست، cooldown و قفل موقت مستثناست.** خواندن هدر IP پروکسی فقط با پیکربندی قابل اعتماد هاست مناسب است؛ این هدرها خودبه‌خود اعتبارسنجی مبدا نمی‌شوند.
- پاکسازی خودکار روزانه لاگ‌های قدیمی با زمان‌بند استاندارد وردپرس (`WP-Cron`)

کپچا مکمل محدودیت ارسال است و باید فعال/پیکربندی شود؛ پیش‌فرض آن خاموش است. این کنترل‌ها تضمین مهار کامل SMS Bombing یا سقف هزینهٔ پنل نیستند: رزرو سهمیه اتمیک برای درخواست‌های هم‌زمان و limiter مستقل دقیقه‌ای در نسخهٔ فعلی وجود ندارد و هر failover ممکن است چند تلاش ارسال ایجاد کند. برای سایت حساس، WAF/Rate Limiting سرور یا CDN و هشدار/محدودیت مصرف پنل پیامکی نیز توصیه می‌شود.

## زمان انتظار و اتصال افزونه‌ها — نسخهٔ ۲.۷.۹

- **بودجهٔ مسیر:** پیش‌فرض ۴ ثانیه برای هر تلاش و ۹ ثانیه برای کل مسیر SMS/بله؛ درخواست‌های داخلی یک درگاه نیز همان بودجه را شریک‌اند. پس از ۲ خطای ارتباطی/سرور، مسیر ۶۰ ثانیه کنار گذاشته و سپس با یک probe هم‌زمان بررسی می‌شود. تنظیمات در تب «پیامک» قابل تغییرند.
- خطای گیرنده/پیکربندی، به‌تنهایی درگاه را برای همه خراب اعلام نمی‌کند. بعد از موفقیت SMS، زنجیرهٔ پشتیبان متوقف می‌شود؛ حالت صریح «هر دو» همچنان کانال دوم را نیز در بودجهٔ مشترک امتحان می‌کند و فقط کانال واقعاً موفق در لاگ ثبت می‌شود.
- پس از ۳ ثانیه انتظار، پیام روشن نمایش داده می‌شود؛ timeout مرورگر، دکمه را آزاد می‌کند ولی درخواست پیامکی خودکار تکرار نمی‌شود. بودجهٔ سرور فقط WordPress HTTP در محدودهٔ ارسال را کنترل می‌کند، نه SMTP، SDK مستقل یا زمان تحویل واقعی پیامک؛ سقف قطعی کل زمان صفحه تضمین نمی‌شود.
- **Dokan:** اتصال اختیاری ورود فروشندهٔ موجود، حفظ نقش و وضعیت فروشندگی و مقصد داشبورد؛ فروشندهٔ غیرفعال به حساب کاربری می‌رود، نه اعطای خودکار مجوز فروش.
- **Paid Memberships Pro:** مقصد بومی حساب/انتخاب پلن؛ ورود عضو منقضی برای تمدید مجاز می‌ماند و دسترسی محتوایی را خود PMPro کنترل می‌کند.
- **Ultimate Member:** کنترل بومی وضعیت حساب قبل از ایجاد نشست برای OTP/رمز/Passkey، محدودیت IP/ایمیل/ورود مدیر و مقصد حساب کاربری.
- **MemberPress:** فقط پل آزمایشی مقصد حساب و جلوگیری از ثبت‌نام عمومی؛ تأیید اتصال واقعی تا دریافت نسخهٔ معتبر انجام نشده است.

اتصال‌ها پیش‌فرض خاموش‌اند و از تب «احراز هویت» فعال می‌شوند. با فعال‌سازی اتصالِ حاضر در سایت، ثبت‌نام عمومی آشنا مسدود می‌شود تا ثبت‌نام، پرداخت و تأیید حساب در افزونهٔ اصلی باقی بماند. فرم اصلی حذف نمی‌شود؛ `[ashna_otp_login]` را در محل مناسب فرم ورود قرار دهید. اولویت مقصد خودکار: فروشندهٔ Dokan، PMPro، UM، MemberPress؛ مقصد صریح/تنظیمات دستی و checkout مقدم‌اند.

[گزارش اجرا، منابع pinned و مرز تست‌ها](docs/delivery-integrations-fa.md) · [توضیحات فنی کامل](docs/product-technical-description-fa.md). تست‌های API/fixture و مرورگر، جای تست staging تمام فرم‌ها، 2FA و افزونه‌های جانبی را نمی‌گیرند. سهمیهٔ اتمیک/بودجهٔ مصرف پیامک همچنان جزو امکانات تحویل‌شده نیست.

## افزودن درگاه پیامک سفارشی توسط توسعه‌دهندگان

به‌واسطه معماری `Ashna_Abstract_Gateway` و متد `Ashna_Gateway_Manager::register_gateway()`، هر توسعه‌دهنده‌ای می‌تواند بدون دستکاری هسته افزونه، درگاه جدیدی را در قالب یا افزونه جانبی ثبت کند:

```php
add_action( 'init', function() {
    if ( class_exists( 'Ashna_Abstract_Gateway' ) ) {
        class My_Custom_SMS_Gateway extends Ashna_Abstract_Gateway {
            public function get_id()    { return 'my_gateway'; }
            public function get_title() { return 'درگاه اختصاصی من'; }
            public function send( $recipient, $code ) {
                // ارسال درخواست وب‌سرویس با $this->http_request(...)
                return true;
            }
        }
        Ashna_Gateway_Manager::register_gateway( new My_Custom_SMS_Gateway() );
    }
} );
```
