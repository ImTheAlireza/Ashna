تصویر نهایی: [ashna-settings-infographic.webp](product-images/ashna-settings-infographic.webp)، با ابعاد **۱۰۰۰ × ۴۲۰۹** و فشرده‌سازی **WebP بدون افت کیفیت**. تصویر از قالب‌های PHP و CSS/JS واقعی پنل با مقادیر پیش‌فرض تهیه شده، نه از نصب زندهٔ وردپرس؛ کلید API، دادهٔ مشتری یا آمار ساختگی ندارد. طرح عمودی با هویت آبی آشنا از چیدمان نمونهٔ ارسالی الهام گرفته؛ تصاویر/متن اختصاصی محصول دیگر کپی نشده‌اند. هیچ مدل مولد تصویر استفاده نشده و بازبینی انسانیِ متن و چیدمان همچنان لازم است.

بازسازی تصویر با Chromium، PHP CLI و Pillow (خروجی‌های میانی فقط در `.cache/settings-capture`):

```sh
# وابستگی‌های Node و jQuery مانند tests/README.md؛ Pillow در PYTHON_BINARY لازم است.
ASHNA_BUNDLED_LIBS=1 node scripts/render-settings-infographic.mjs
```

رندرگر از `PHP_BINARY` و `PYTHON_BINARY` پشتیبانی می‌کند؛ پیش‌فرض ابزارهای کش‌شدهٔ محیط توسعه‌اند. فونت Vazirmatn نسخهٔ v33.003 از مخزن رسمی GitHub در cache دریافت می‌شود. ابعاد، سلامت فونت/تصویر، سقف حجم و برابری پیکسل‌های PNG اولیه با WebP بررسی می‌شوند. این رندر، تست عملکرد درگاه یا تأیید نصب واقعی نیست.

## نصب و ارتقای امن

۱. از فایل‌ها، دیتابیس، تنظیمات و فایل رسمی لایسنس بکاپ بگیرید؛ ابتدا روی staging آزمون کنید.
۲. نسخهٔ قبلی را **غیرفعال** کنید، نه حذف؛ uninstall ممکن است داده‌ها را پاک کند. دو نسخه را هم‌زمان فعال نکنید.
۳. پوشهٔ کامل `ashna-otp` را نصب کنید؛ فایل‌های دو نسخه یا دو پوشه را مخلوط نکنید.
۴. در edition لایسنس‌دار، فایل رسمی متناظر را کنار `ashna.php` قرار دهید؛ سپس افزونه را فعال کنید.
۵. کش سایت/CDN/مرورگر را پاک و کاربران قبلی، شماره‌ها، Passkey، سبد خرید، شورت‌کدها و صفحات المنتور را بررسی کنید. برای پاک‌کردن پوشهٔ قدیمی uninstall اجرا نکنید.

حداقل وردپرس نسخهٔ لایسنس‌دار ۵.۸ و **PHP 8.2** است؛ PHP هاست با نصب افزونه تغییر نمی‌کند. ionCube Loader وب باید با PHP و فایل لایسنس سازگار باشد؛ تمام نسخه‌های جدیدتر PHP تضمین نشده‌اند. edition بدون لایسنس حداقل PHP 7.4 دارد.

فایل رسمی `RTL_License_c1595a7238d64f3a.php` در مخزن موجود نیست. هویت، هش `4f106eb02a251f2a6951ca3f530596590081002d` و شرط `isActive() === true` دست‌نخورده‌اند؛ بستهٔ لایسنس‌دار تا افزودن فایل معتبر آمادهٔ انتشار نهایی نیست. فایل جعلی ساخته نمی‌شود.

## قرارداد فنی و محدودیت‌ها

### نشست، مجوز و سازگاری داده

ورود OTP/رمز/Passkey از `Ashna_Session::login` و کوکی استاندارد وردپرس با `WP_Session_Tokens` استفاده می‌کند؛ JWT یا PHP Session موازی ندارد. نقش/capability حساب موجود حفظ می‌شود؛ ثبت‌نام عمومی فقط customer/subscriber می‌سازد. در صورت وجود session فعال ووکامرس، API عمومی انتقال نشست مهمان اجرا می‌شود. `wp_login` برای بازیابی سبد ذخیره‌شده و nonce تازه برای درخواست بعدی AJAX حفظ شده‌اند. nonce و redirect جای permission سمت سرور نیستند.

سیاست‌های `wp_authenticate_user`، spam در multisite و `ashna_authenticate_user($user, $method)` پیش از کوکی بررسی می‌شوند؛ مسیر OTP/Passkey اجرای کامل زنجیرهٔ `authenticate` تمام افزونه‌ها نیست. `ashna_otp_login_redirect($redirect, $user)` و `ashna_otp_user_registered` نقاط توسعه‌اند؛ رویداد ثبت‌نام پس از ایجاد کاربر است، نه validation پرداخت/تأیید. کوکی مسدود، هدر ارسال‌شده یا نبود OpenSSL در Passkey باعث رد ورود می‌شود.

ذخیره‌سازی فیزیکی قبلی تنظیمات، لاگ‌ها، شماره‌ها، Passkey/ایندکس credential، challenge، token و transientها درجا حفظ می‌شود؛ schema همچنان ۲.۳.۰ است و مهاجرت مخرب نداریم. aliasهای قبلی شورت‌کد/کلاس/هوک/ویجت المنتور باقی‌اند؛ فیلترهای قبلی پیش از جدید و رویدادهای هر دو namespace یک بار اجرا می‌شوند. مسیر قالب `yourtheme/ashna/login-form.php` اولویت دارد و مسیر قبلی fallback است. CSS ذخیره‌شده هنگام نمایش تبدیل می‌شود و ترجیحات مرورگر بدون بازنویسی مقدار جدید مهاجرت می‌کنند. CSS مستقل قالب و کش سایت باید جدا بررسی شوند.

### کنترل ارسال و Brute Force / SMS Bombing

| کنترل | پیش‌فرض |
|---|---|
| سقف هر شماره/ایمیل | ۵ درخواست در ساعت گذشته |
| سقف هر IP | ۱۵ درخواست در ساعت گذشته |
| `resend_cooldown` | ۶۰ ثانیه |
| `max_verify_attempts` | ۵ تلاش ناموفق |
| `lockout_duration` | ۹۰۰ ثانیه، معادل ۱۵ دقیقه |
| `otp_expiry` | ۱۲۰ ثانیه |

این کنترل‌ها در سرور پیش از ارسال عادی اجرا می‌شوند و قابل تنظیم‌اند. محدودسازی فعلی **ساعتی** است، نه limiter مستقل دقیقه‌ای. رکورد failed در شمارش ساعتی هست، ولی آخرین failed انتظار cooldown ایجاد نمی‌کند. لیست سیاه الگوی `*` دارد؛ **لیست سفید با تطبیق دقیق از سقف درخواست، cooldown و قفل موقت مستثناست**. کپچا پیش‌فرض `none` است؛ Turnstile، reCAPTCHA v3، آرکپچا و کپچای ریاضی باید فعال/پیکربندی شوند.

شمارش از لاگِ پس از dispatch است و **رزرو اتمیک سهمیه/بودجهٔ هزینه نداریم**؛ رقابت هم‌زمان یا failover می‌تواند مصرف بیشتری ایجاد کند. تضمین مهار کامل SMS Bombing یا عدم تخلیهٔ شارژ داده نمی‌شود. `trust_proxy_headers` فقط پشت پروکسی قابل اعتماد با حذف/بازنویسی هدرهای ورودی و جلوگیری از دسترسی مستقیم به مبدا مناسب است؛ در اتصال مستقیم خاموش شود. این گزینه مبدا هدر را خودکار اعتبارسنجی نمی‌کند. برای سایت حساس، WAF/Rate Limiting و هشدار/سقف مصرف سرویس‌دهنده نیز لازم است.

### زمان انتظار زنجیره

| تنظیم | پیش‌فرض | بازهٔ تنظیم |
|---|---|---|
| `delivery_attempt_timeout` | ۴ ثانیه | ۱ تا ۱۵ |
| `delivery_total_timeout` | ۹ ثانیه | ۳ تا ۳۰ |
| `delivery_failure_threshold` | ۲ خطای واجد شرایط | ۱ تا ۱۰ |
| `delivery_circuit_seconds` | ۶۰ ثانیه | ۱۰ تا ۶۰۰ |

درگاه اصلی و حداکثر سه پشتیبان **ترتیبی** هستند؛ اولین موفقیت SMS زنجیره را متوقف می‌کند. timeout خام ۱۵ ثانیهٔ درایورها در scope ارسال به بودجهٔ باقی‌مانده محدود می‌شود؛ درخواست‌های داخلی توکن/retry بودجهٔ جدید نمی‌گیرند و redirect HTTP دنبال نمی‌شود. حالت صریح «هر دو» کانال دوم را هم در بودجهٔ مشترک امتحان و فقط کانال موفق را ثبت می‌کند.

Circuit Breaker خطای ارتباطی، HTTP 5xx/429 و خطای اجرایی درایور را می‌شمارد؛ خطای گیرنده/تنظیمات به‌تنهایی خرابی عمومی نیست. probe بازیابی lease دیتابیسی دارد و حذف آن مقایسه‌ای است؛ شمارندهٔ transient تقریبی است، نه کنترل اتمیک همهٔ ارسال‌ها. تغییر تنظیمات وضعیت سلامت را با HMAC جدا می‌کند. تست صریح مدیر از مدار عبور می‌کند، نه از بودجه.

رابط پس از ۳ ثانیه پیام انتظار دارد و دوباره‌فرستی همان فرم را مهار می‌کند. timeout AJAX برابر بودجهٔ مسیر + ۳۰ ثانیه است؛ تکرار خودکار انجام نمی‌شود. **نتیجهٔ نامعلوم** پس از timeout همچنان ممکن است؛ idempotency سراسری و عدم ارسال/هزینهٔ تکراری تضمین نشده‌اند. SMTP، SDK مستقل، DNS/transport یا هاست سقف قطعی ندارند. بودجهٔ API، زمان تحویل پیامک نیست و benchmark واقعی p50/p95/p99 انجام نشده است.

### اتصال حساب‌های موجود

اتصال‌ها در «احراز هویت» **پیش‌فرض خاموش‌اند**. با فعال‌سازی اتصالِ موجود در سایت، ثبت‌نام عمومی آشنا حتی با `auto_register` روشن مسدود می‌شود؛ ثبت‌نام تخصصی، پرداخت و تأیید در افزونهٔ اصلی باقی می‌مانند. فرم اصلی حذف نمی‌شود؛ `[ashna_otp_login]` را در محل مناسب قرار دهید.

- **Dokan:** تشخیص فروشنده با API بومی؛ فروشندهٔ فعال به داشبورد و غیرفعال به حساب ووکامرس می‌رود. نقش و مجوز فروش تغییر نمی‌کند.
- **Paid Memberships Pro:** تابع بومی `pmpro_login_redirect` مقصد حساب/انتخاب پلن را می‌دهد؛ عضو منقضی می‌تواند برای تمدید وارد شود و کنترل محتوا با PMPro است.
- **Ultimate Member:** سیاست بومی وضعیت حساب پیش از کوکی در سه روش ورود، محدودیت IP/ایمیل/ورود مدیر و مقصد account؛ تمام redirectهای نقش/فرم و افزونه‌های جانبی پوشش ندارند.
- **MemberPress:** فقط پل آزمایشی گزینهٔ صفحهٔ حساب و منع ثبت‌نام عمومی؛ نسخهٔ معتبر موجود نیست و سازگاری واقعی تأیید نشده است. این مورد در متن امکانات قابل فروش درج نشده است.

اولویت مقصد خودکار: فروشندهٔ Dokan، PMPro، UM و MemberPress؛ مقصد صریح معتبر، تنظیمات دستی و checkout مقدم‌اند. سیاست فعال حساب UM مستقل از مقصد است. ورود، جای permission یا 2FA نیست؛ افزونه‌های جانبی تأیید حساب نیازمند اتصال/تست جدا هستند. تأیید OTP در ثبت‌نام تخصصی و نصب end-to-end همهٔ ترکیب‌ها تحویل نشده‌اند.

## تست و بازسازی

دستورها، منابع pinned و مرز fixture/تست واقعی در [tests/README.md](tests/README.md) و `tests/fixtures/ecosystem-sources.json` هستند. تست‌ها APIهای WP 6.8.3 و WC 9.9.5 و توابع pinned Dokan/PMPro/UM را با DB/transport شبیه‌سازی‌شده به کار می‌گیرند؛ تست هاست، اپراتور، پرداخت، Redis، چندworker، فایل RTL یا نسخهٔ واقعی MemberPress نیستند. کد محصولات ثالث فقط در `.cache` دریافت می‌شود و داخل Git/ZIP نیست.

```sh
# از ریشهٔ مخزن؛ PHP_BINARY را به PHP CLI مناسب تنظیم کنید.
python tests/check-technical-description.py
python tests/check-rtl-description.py
python tests/prepare-session-tests.py
python tests/prepare-ecosystem-tests.py
python tests/run-session-integration.py
python tests/run-delivery-ecosystem.py

npm ci --prefix product-images/gallery-design
ASHNA_BUNDLED_LIBS=1 node scripts/render-help.mjs
python scripts/package-deliverables.py --plugin-only
python scripts/package-deliverables.py --without-license --plugin-only
python scripts/package-rightchin.py
python tests/check-ashna-brand.py
```

رندر PDF، شمار سه صفحه، فونت/تصویر، اعداد فارسی و سرریز/فاصلهٔ پاورقی را بررسی می‌کند. بسته‌بندی CRC، برابری بایتی فایل نصب داخلی و SHA256 را کنترل می‌کند. این بررسی‌ها به معنی تأیید فایل لایسنس یا پذیرش محتوا و تصاویر توسط راست‌چین نیستند. گزارش‌های مقطعی حذف شده‌اند؛ تاریخچهٔ آن‌ها در Git باقی است و توضیحات نگهداری فقط در این README و راهنمای تست‌ها متمرکز شده‌اند.
